Share one workspace across three, four or more computers, and manage every member from the computer you are using. This release expands the two-computer design in v0.4.11 and adds optional shared clipboard, experimental macOS builds, Ubuntu tray integration and a repaired Windows rendering path.

### A workspace with more computers

- Link additional computers with an approved invitation and a displayed security code. The overview shows every member's platform, version, connection status and device roles, with **Switch here** and **Settings** actions for each computer.
- The workspace fills the main window. Its header retains the original icon, shows the installed version and provides **+ Add a computer** and a Settings gear. Settings opens over the workspace; **Advanced → Diagnostics** keeps detailed state and logs available there.
- **+ Add a computer** has separate **Nearby computers** and **Manual IP** views. Manual entry accepts numeric IPv4 or IPv6 addresses with an optional port, validates input, and shows pending approval, success and errors. An explicit address can reconnect the saved coordinator while automatic connection is disabled, without changing the pinned identity.
- Control, input, system audio and microphone listeners support IPv4 and routable IPv6 (global or ULA). Cross-computer translation of IPv6 link-local interface scopes is not implemented; use IPv4 or a routable IPv6 address when members have different interface scopes.
- Choose the physical keyboard/mouse source once, switch directly to a member, cycle connected computers with F12 or use screen-edge crossing. F11 returns input to the source. Offline or incompatible members are excluded from active device routes.
- Choose one headphones/speakers computer and hear every other eligible online computer there. Its level controls the real system output; every source has independent relative volume and mute. A 90% system level and 50% relative level retain the intended 45% relationship.
- Share one selected physical microphone with every capable online recipient through its virtual microphone. A disconnected or unplugged source does not silently open a different microphone.
- Change shared choices, device bindings, application preferences and updates from any member. Select the computer in Settings; **Download and install** updates that selected computer, even when the computer you are using is already current. Remote completion is confirmed after the target reconnects with the requested version.
- One coordinating computer must keep Desk Switch running for membership, settings, switching requests and clipboard delivery. Input, sound and microphone streams connect directly between their endpoints. Automatic coordinator replacement is not implemented; update and restart the coordinator last.

### Shared clipboard

- **Shared clipboard** is off by default. Enable it to synchronize plain text and PNG images across online members, with an 8 MiB transfer limit and a 4096 × 4096 image limit. Disabled sharing does not open the native clipboard, and received content is not echoed around the workspace.
- GNOME Wayland uses the bundled **Desk Switch Tray** companion; Windows, macOS and supported X11 sessions use native clipboard backends. Enable the companion once in GNOME **Extensions**. Log out and back in if the newly installed extension is not listed yet.
- File and folder transfer is deferred and tracked in [issue #2](https://github.com/siarheisinelnikau/desk-switch/issues/2).

### Tray, rendering and installers

- Ubuntu GNOME left-click opens the application's quick-controls popup; right-click keeps the standard native menu. The companion also raises only Desk Switch's own windows when activation is requested. Other desktop environments retain their tray host's behavior.
- **Open Desk Switch**, popup X and **Quit application** wake the main dispatcher even while its window is hidden. Closing the main window keeps sharing in the tray; explicit Quit releases input and stops services.
- Windows uses a native CPU/GDI rendering path for the main window and quick controls, with explicit handling of hidden windows, restoration and retained textures. Bounded local tests cover lifecycle transitions and settled/hidden paint behavior. The reported physical-machine combination of a white main window and black popup was not reproduced in those isolated tests; target-machine confirmation remains necessary.
- **VB-CABLE installers… → Run official installer** opens the saved original vendor installer on the selected Windows or macOS computer, locally or remotely. Complete its normal operating-system authorization and installer steps there. Extraction and the official website download remain available; opening an installer does not claim that the driver is installed.
- Startup and periodic update checks fetch signed metadata only. Installer download, verification, installation and restart begin only after an explicit action for the selected computer. Checks can be disabled persistently, while manual checking remains available.

### Monitor switching

- A participating destination selects its own saved monitor port with one serialized VCP `0x60` write. Rapid requests cannot queue repeated selections; startup, idle and switch confirmation perform no DDC polling. Failures do not probe alternate ports, retry automatically or reverse a selection.
- Saved monitor connections and an explicit **Read the current input once** request can be managed for any selected online computer from another member. Reading does not switch the monitor.
- This does not repair monitor firmware. The confirmed LG 27GK750F workaround remains to select **DisplayPort once with the monitor's own joystick**; that cleared the reported **Out of range** warning before subsequent application switches. Persistence after monitor power-off has not been verified.

### macOS — experimental

- Separate native application ZIPs support **Apple Silicon and Intel on macOS 13 or newer**. Native adapters cover input, system audio, microphone, supported external-monitor DDC/CI, the system clipboard, menu-bar controls and optional login startup. The README describes permission requirements and adapter limits.
- **macOS functionality has not been tested on physical hardware.** Compile, unit and packaging checks do not verify real devices, monitor firmware, audio quality, permissions or settled/hidden performance on a Mac. Mac testing reports and pull requests are appreciated.
- App bundles and embedded helpers are ad-hoc signed, **not Developer ID signed or notarized**. First launch uses macOS's normal security approval flow. Updates verify the existing pinned project signature, replace the complete bundle, preserve settings and retain a rollback copy until the new GUI confirms startup. Use a writable Applications location such as `~/Applications`; permissions are never bypassed.

### Upgrade and downloads

Install **0.5.0 on every intended member before using the larger workspace**. The saved v0.4.11 partner remains available through the limited legacy management/update bridge during the upgrade; device sharing waits for matching versions. Existing identities and preferences are preserved. Keep the coordinating computer running and restart it last.

- **Windows x86-64:** `desk-switch-v0.5.0-windows-x86-64.exe`
- **Ubuntu 24.04/26.04 x86-64:** `desk-switch-v0.5.0-linux-x86-64.deb`
- **macOS 13+, Apple Silicon — experimental:** `desk-switch-v0.5.0-macos-arm64.zip`
- **macOS 13+, Intel — experimental:** `desk-switch-v0.5.0-macos-x86-64.zip`

The existing Ed25519 updater identity is retained. The release pipeline requires all four native artifacts and verifies their exact signed sizes and hashes, platform/architecture, embedded build stamps, Debian metadata and macOS bundle/helper contents before stable publication.

Release requests can be held with `"hold": true` in `release/publish-request.json`, which skips native builds, signing and publication. Omitting `hold` or setting it to `false` enables the normal pipeline. A newer request on the same Git ref cancels an unfinished older run; already published releases and assets are preserved.

### Validation

Local focused checks cover four encrypted loopback members, group settings and routes, explicit pinned-controller reconnection, manual-address validation, metadata-only update checks, selected-computer installation, update/restart coordination, native input recovery and the Windows renderer. Native listener checks authenticate IPv4 and IPv6 peers and transfer PCM without physical audio hardware. Clipboard and GNOME companion checks use synthetic data, mocked Shell objects and private D-Bus sessions; they do not access the user's clipboard or physical monitor. Bounded Windows visible/hidden checks provide renderer lifecycle evidence, not a physical multi-computer hardware test. Final native CI must pass strict linting, unit tests, optimized builds and package verification on Ubuntu, Windows, Apple Silicon and Intel macOS before publication. Real multi-computer devices, GNOME routing, audio quality and monitor firmware still need target-machine validation.
