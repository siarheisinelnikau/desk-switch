Desk Switch 0.6.0 adds a saved display arrangement for multi-computer workspaces, with precise screen-edge handoffs and graceful input returns. These changes build on v0.5.1.

### Arrange your displays

- Open **Settings → Arrange displays…**, or use the action beside **Move between computers at the screen edge**. Drag groups into place, use **Left**, **Right**, **Above** or **Below**, or nudge them with the keyboard. Apply saves the arrangement for the workspace; Cancel or Escape discards edits.
- Touching edges allow handoffs in all four directions, including partial edge contacts and displays of different sizes. The pointer enters the exact destination display at the corresponding position, inset from the opposite edge. Holding a key or mouse button suppresses a cross-computer handoff; gaps keep edges closed.
- Displays belonging to one computer move together and preserve that computer's OS arrangement. Participating computers share **one physical-monitor rectangle**, anchored to the last successfully selected computer. Entering that rectangle controls the computer already shown there; changing its monitor input remains an explicit workspace switch.
- Applying an arrangement or entering an ordinary display sends **no monitor-input command**. Desk Switch does not change resolution, refresh rate, rotation or OS display settings. If the shared monitor's current computer is unknown, choose **Switch here** from the computer whose picture is visible first.

### Input reliability

- Normal returns to the physical keyboard/mouse owner use a graceful, generation-bound return instead of emergency recovery. Returning while a receiver is still preparing also cancels that transfer without replacing the authenticated connection. **F11** remains the emergency action.
- Stale geometry, activation changes and late acknowledgements are checked before accepting pointer-placement requests. Optional placement failures keep the current input session usable and show an error. Offline or ambiguously mapped displays receive no automatic handoffs.
- Windows receiving input now guards the actual accelerated motion produced by Desk Switch, including queued motion at display boundaries. Relative input retains the receiving computer's normal pointer speed and acceleration. The guard does not intercept another application's or a local mouse's motion.
- Ubuntu GNOME maps Mutter's display geometry to the portal's unique EIS regions. The updated companion supplies read-only initial pointer observation. Unsupported mappings disable the affected edge while relative input, manual switching and F12 remain available.
- Runtime routes are cached and refreshed when relevant geometry or ownership changes. Arrangement adds no DDC polling or idle graph rebuilding.

### Interface and documentation

The arrangement controls and errors are available in all six UI languages. The shorter README keeps the workspace, tray and settings screenshots; the [full guide](https://github.com/siarheisinelnikau/desk-switch/blob/v0.6.0/docs/guide.md) covers setup, permissions and monitor limitations.

### Upgrade and downloads

Install **0.6.0 on every workspace member** before using the new routing. Update other members first and the **coordinating computer last**. Device protocol is now **8**; workspace management remains protocol **1**. Settings and pinned identities are preserved.

On Ubuntu GNOME, reload the bundled **Desk Switch Tray** companion after updating: toggle it off and on in **Extensions**, or sign out and back in. This loads companion version 2 and its pointer-observation support.

- **Windows x86-64:** `desk-switch-v0.6.0-windows-x86-64.exe`
- **Ubuntu 24.04/26.04 x86-64:** `desk-switch-v0.6.0-linux-x86-64.deb`

This release ships Windows and Ubuntu only. Experimental macOS source remains excluded from releases.

### Validation and limits

The optimized Windows suite passed **231 tests**; the separate bounded native-window test also passed. Strict Clippy, 23 release-tool tests and the mocked GNOME companion suite passed. Actual CPU/GDI application fixtures settled at zero UI frames during six-second visible, hidden and restored samples. Native Windows/Ubuntu builds, packages and signatures gate publication. These checks do not verify physical cross-PC input, monitor firmware or audio quality. The LG **Out of range** workaround remains selecting DisplayPort once with the monitor's joystick.
