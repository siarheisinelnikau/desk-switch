This update fixes input-receiver shutdowns and workspace connection handovers, makes shared-monitor switching use one command through the visible connection, and restores the original device icons and monitor view across the workspace and tray popup.

### Input and connection reliability

- Input receivers are no longer treated as input hosts merely because they report an authenticated peer. Host-only switch and return commands are sent only to the physical input source. This removes a planner path that could stop a receiver and produce EOF immediately after a handoff, including Windows → Ubuntu.
- Replacing a workspace control connection keeps the previous link alive until traffic confirms that the peer has activated its replacement. A late close from an obsolete connection cannot mark the new connection or the other workspace members offline. A failure of the current connection still triggers normal offline handling and reconnection.
- Simultaneous connection attempts are bounded, and known-peer transport closures produce reconnect diagnostics. Authentication and protocol errors remain errors. Recent network context is available under **Settings → Advanced → Diagnostics**.

### Shared-monitor switching

- One designated computer sends one VCP `0x60` selection through the monitor connection whose picture is currently visible. The destination's saved input is used, and shared input waits for the writer's completion and the settling interval. The application does not try another connection automatically after a failure.
- An already confirmed destination does not receive another monitor write when only input needs to move. Input recovery does not issue a video-switch command.
- Issuance is recorded before the native command starts. Reconnecting or restarting the writer cannot replay an unfinished command. A timeout interrupts the request and blocks another switch until the writer confirms cancellation or its bounded job exits; reopen Desk Switch on that writer if it is offline.
- When no successful monitor selection is known, including an upgrade from 0.5.0, the authenticated computer making the explicit request establishes the initial visible source. **Make that first request from the PC whose picture is on the monitor.** Manual monitor-menu changes cannot be inferred automatically.
- Errors keep bounded command/device details in Diagnostics and hover text, while the main view shows a concise failure and retry action. This changes application command handling; monitor firmware still determines DDC/CI behavior. The documented LG 27GK750F workaround remains to select DisplayPort once with the monitor's own joystick.

### Original device views

- Restored the original outline keyboard, mouse, headphones, microphone, monitor and PC-tower artwork in the main workspace and quick-controls popup. Source colours agree across computer cards, device toggles and per-computer volume rows. Muted sound and microphone sources have a subdued colour and slash.
- The shared-monitor view separates the last successful selection from a requested destination, pending work, interruption and failure. The main view wraps its participating-computer symbols for larger workspaces; the tray uses a compact monitor/status view. Monitor connections remain configured in each computer's existing Settings.
- Quick controls stay within the monitor's work area on smaller screens. **Open Desk Switch** and **Quit application** remain visible and clickable while longer content scrolls above them.
- The shared-clipboard hint is now simply **Text and images.** The existing opt-in text/image sharing is unchanged; file transfer remains tracked in [issue #2](https://github.com/siarheisinelnikau/desk-switch/issues/2).

### Upgrade and downloads

Install **0.5.1 on every workspace member** for input and media sharing. Update the other members first and the coordinating computer last. Updated members accept older management/state messages during the upgrade, but an older snapshot without an explicit monitor command cannot authorize a new DDC write. Complete the upgrade before using the revised monitor workflow. Settings and pinned identities are preserved.

- **Windows x86-64:** `desk-switch-v0.5.1-windows-x86-64.exe`
- **Ubuntu 24.04/26.04 x86-64:** `desk-switch-v0.5.1-linux-x86-64.deb`

**This release ships Windows and Ubuntu only.** macOS release builds are deferred until support is ready for stable use. Experimental Mac source and manual checks remain available; no macOS ZIP is published for 0.5.1. The existing pinned Ed25519 updater identity is retained for both installers.

### Validation

The optimized Windows test suite passed 197 tests with one ignored, and strict Clippy passed. Coverage includes receiver/host role handling, connection-replacement event orders, explicit monitor-writer selection, no replay, settling/cancellation and popup footer visibility. Hardware-free Python release checks passed for native artifact identity, architecture and build stamps, historical manifest compatibility, canonical asset names and preservation of signed release notes; packaging/signing scripts passed Python syntax checks. The Windows release job also checks native 16/32-pixel executable icons against the original artwork and verifies version/branding metadata before upload, without launching the application. Both native builds and package/signature checks must pass the release pipeline before publication. These checks do not establish physical Windows–Ubuntu switching, audio quality or monitor-firmware behavior on the user's setup.
