Desk Switch 0.6.1 fixes a workspace reconnection failure that could prevent Ubuntu from staying connected to Windows after switching input or restarting a computer.

### Fixed

- Reconnecting computers no longer compare a peer's greeting acknowledgement against an older local activation counter. The coordinator's full workspace snapshot supplies the authoritative input readiness and monitor result.
- Newly invited computers cannot bring readiness or monitor results from an unrelated workspace into the new session. Reconnection preserves existing coordinator-owned monitor failures and the single-writer monitor safeguards.
- Delayed interface status updates keep their fresh hardware information without restoring an obsolete activation counter or monitor result after synchronization.
- This resolves the `Invalid monitor acknowledgement` failure and the corresponding repeated `unexpected end of file` reconnect cycle for this case. Other network failures still report their actual cause.

### Upgrade

Update every workspace member to **0.6.1**, with the coordinating computer last. Saved settings, identities and display arrangements are preserved; device protocol remains **8**, workspace protocol **1**.

Display arrangement and shared-monitor behavior are unchanged from 0.6.0.

Downloads are **Windows x86-64** and **Ubuntu x86-64** only. macOS remains excluded from releases.

### Validation

The optimized Windows suite passed **233 tests**, including two authenticated loopback regressions using the reported counters and a delayed interface update. Both test cases verify settings in both directions without driving input devices or monitors. Native Windows and Ubuntu checks gate publication.
