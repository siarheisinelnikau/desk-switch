Monitor switching now avoids automatic DDC reads and competing recovery commands, addressing unnecessary monitor traffic reported with HDMI/DisplayPort switching.

### Fixed

- The active video port issues one selection command for the destination's saved input, in both directions. The second PC is used only if no native command could be issued; an error after issuance never triggers another write.
- Switch readiness uses a short settling interval and the authenticated application connection. It no longer waits for unreliable input readback or skips selection because an inactive port reports a stale value.
- Removed startup and background monitor status reads, including the GUI's automatic status query. Reading the current connection remains available explicitly during setup.
- Only an active input receiver may issue one recovery selection after connection loss. Source-side recovery no longer races it, and monitor-only failures do not reverse the display automatically.
- A slow or abandoned DDC call cannot queue more selections. Linux ddcutil children stop when their owning worker exits; automatic communication probes, verification and write retries are disabled.
- Diagnostics distinguish selection requests, issued Windows API calls and Linux ddcutil processes.

### Upgrade

Install **v0.4.10 on both PCs** for device sharing (**protocol 7**). The independent management connection remains compatible with v0.4.9, allowing settings and signed updates to be managed while versions differ.

- **Windows x86-64:** desk-switch-v0.4.10-windows-x86-64.exe
- **Ubuntu 24.04/26.04 x86-64:** desk-switch-v0.4.10-linux-x86-64.deb

### Known limitation

A recurring **Out of range** message on the reported LG 27GK750F is still awaiting hardware validation. Other LG models have [reported the same symptom after a single standard DDC command](https://github.com/rockowitz/ddcutil/issues/102). The application does not change video modes or send unverified LG-specific commands. If the warning persists after both applications exit, select the intended input using the monitor's own menu or power-cycle it.

Synthetic handoff tests exercise both directions, slow writes, errors after issuance, cancellation and connection loss without contacting a physical monitor. Native Windows and Ubuntu checks and package verification run before publication.
